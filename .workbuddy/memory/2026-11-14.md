## Yukari WebUI（Material 3 Expressive）

- 新增 `module/webroot/`：`index.html` + `assets/style.css` + `assets/app.js`，三视图
  （应用 / 设置 / 关于），底部导航 + hash 路由（`#apps` / `#settings` / `#about`）。
- 新增 `module/webui.sh`：`info` / `targets` / `apps` / `save '<json>'` / `force-stop`。
  `targets` 用 `tr '\n' ' ' + sed` 兼容单行与缩进两种 config 格式；`save` 先写
  `config.json.tmp` 再 `mv`，并 `chmod 0644`、`chown 0:0`、best-effort `chcon system_file`。
- 前端通过 `ksu.exec` 兼容层工作（同时接受 `(errno,stdout,stderr)` 回调、`{errno,...}`
  返回值与 Promise），无桥接时进入预览模式用内置示例数据渲染，便于浏览器调试。
- `action.sh` 先尝试 KSU WebUI Standalone（`io.github.a13e300.ksuwebui/.WebUIActivity -e id Yukari`）
  或 WebUI X（`com.dergoogler.mmrl.wx/.ui.activity.webui.WebUIActivity -e MOD_ID Yukari`），
  都缺失时退回原来的终端流程。`customize.sh` 给 `webui.sh` 设 0755。
- 打包：`scripts/package.sh` 复制 `webui.sh` 与 `webroot/{index.html,assets/style.css,assets/app.js}`；
  `verify_package.sh` 把它们加入 required；`tests/build/package_test.sh` 夹具同步；
  `tests/native/run.sh` 的 `bash -n` 增加 `webui.sh`、`customize.sh`、`service.sh`。
- 文档：中英文 README 增加 WebUI 章节，`docs/build.md` 说明打包内容与权限。
- 本机验证：Windows 上没有 g++/readelf，`tests/build/package_test.sh` 无法完整运行；
  用替身工具链 + 手工 ZIP 验证了 `verify_package.sh`。ZIP 内的 webroot 文件权限为 0644，
  脚本 0755。

## WebUI 第二轮：作者 / 版本 / Monet 配色 / 圆角

- `module.prop`：`author=秋山葉桜`、`version=2.0.0`、`versionCode=2`；`module/build.gradle.kts`
  同步 `versionCode 2` / `versionName "2.0.0"`；`webui.sh info` 新增 `author=`，
  关于页的「作者」胶囊由运行时数据填充（`#about-author`），不再硬编码。
- 新增 `tools/monet.py`（仅本地，不进 ZIP）：移植 material-color-utilities 的 CAM16/HCT，
  按 TonalSpot 2025 输出 34 个颜色令牌。与官方 `@material/material-color-utilities` 0.4.0
  的 `SchemeTonalSpot(spec: 2025)` 逐色比对，最大差 3/255（深色 tertiary 因色域边界）。
  种子 `#6a49c8`（原品牌紫）。`--seed` 换色、`--verify` 比对 style.css 是否同步。
- 两个刻意的偏离（已在脚本注释说明）：深色 `tertiary-container` 用 tone 30（官方输出
  与浅色相同 83.9，会在深色界面放一块浅粉面板）；`inverse-primary` 沿用 2021 的 80/40。
- 形状：`--radius-xs/sm/md/lg/lg-increased/xl/xl-increased/full` = 4/8/12/16/20/28/32/999，
  状态面板（`.hero`）从 `34px 34px 34px 14px` 改为统一的 `var(--radius-xl)` 28dp。
- 踩坑：Windows 上 Python `write_text` 会把 `\n` 写成 CRLF，导致 module.prop 等文件混入
  `\r`；已统一回 LF，并在 `.gitignore` 加 `__pycache__/`。清理时误改过 `module/.cxx` 里的
  `.o`，已整个删除（CMake 缓存可重生成）。
- 截图注意：headless Chrome 的 `--virtual-time-budget` 会冻结 CSS 过渡，开关会停在过渡
  起始态，看起来像「未开启」。预览时注入 `*{transition:none}`（含 `::before`）才是终态。
